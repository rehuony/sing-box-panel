# sing-box-panel design system

The design system of the sing-box-panel web interface: roles, scales, formulas, patterns and rules. It extends the global design guide and repeats nothing from it. Every value is the one the tokens in code use; a change to one changes the other in the same work.

The panel interface serves two scopes. The panel scope covers the fleet: the nodes home, subscriptions, the panel log and panel settings. The node scope covers one node: its overview, core versions, configuration, logs and settings. The node console is a separate interface that one node serves on its own host for its enrollment with a panel and a read-only view of its state; it uses the same tokens, type and components, and the panel's command line shares its terminal parts.

## 1. Character

| Property | Declaration |
| --- | --- |
| Mood | Calm and technical; the interface reports state and stays out of the way |
| Colour temperature | The terminal's cool neutral greys, the same under every accent |
| Density | Dense working screens; data at 12–14px, one title strip per view |
| Type | One bundled variable sans at three weights; one bundled monospace for machine text |
| Surface material | Content surfaces (cards, tables, forms, panes, title strips, key figures) at 90% opacity over a canvas that carries a faint glyph field, separated by hairlines; the status line, fields, menus, dialogs and toasts stay opaque, and floating layers detach from the window edge and cast a shadow |
| Motion | Immediate response to input, short state transitions; the glyph field's slow rewriting is the only idle motion |

Properties that make the product recognisable:

- The neutral scale is the terminal's greys and the saved accent touches only actions, selection and focus, so every palette keeps the same calm surfaces and accessible text; status colours never take the accent, so a state reads the same under every palette and in both themes.
- A field of protocol glyphs sits behind every view, interactive at sign-in and calm once signed in, where it mixes in the product's own values; both services read as one product.
- One radius parameter derives three corner steps, so a single setting reshapes every element in proportion.
- Every view declares its scope: one status line below the workspace lists the scope's numbered windows, leads back to the fleet, in a node's windows also to the neighbouring nodes, and opens a command box floating near the window's top, and a node window's title strip carries the node's identity and state. The shell works like a terminal multiplexer: the panel's command line and the node console share one prompt, buffer and completion grammar, and nodes appear as terminal panes whose labelled readings follow the console's status output.

Accent policy: at rest a view shows only neutrals and the one accent, besides the cell meter's scale. The one primary action of an area takes the accent's tint: its soft fill, a 50% accent hairline and accent text, the tint of a selected pane, as a destructive action takes the danger tint; on hover the accent at 15% deepens it. The accent marks selection, the current window, a pressed toggle and a filter in effect through its soft fill, turns a control's own hairline to it under keyboard focus, or turns the hairline of a tab, pane or card to it, colours links and the prompt's cursor. It never tints a neutral, marks a state, a badge, the logo, a data series or a destructive action. Interaction states read the same in every component: hover and a highlighted option take the hover wash; selected, current, pressed and on take the accent's soft fill, except a tab bar's current tab, which is its raised neutral thumb; a checked option shows its checkmark; text keeps the text colour in all of them; only the primary action, links and the prompt write in the accent. State colours mark only the exception (a dot, a word), never a border or a filled region; the cell meter's scale is the one place they blend. Data series take the highlights: cyan for download and the first series, magenta for upload and the second, yellow for the third; a download or upload reading anywhere takes its series' colour on its arrow and, unless zero, on its value, so a reading matches its chart, and lists download first.

State colours, shared by runtime and node connection states in every theme and palette:

| State | Colour |
| --- | --- |
| Running, online, healthy | Success |
| Degraded, stale, restart required | Warning |
| Failed, unreachable | Danger |
| Stopped, disabled | Muted text |
| Unknown, not yet reported | A hatch of 1px strong border lines every 3px over raised surface, in a meter's cells and a timeline's slots alike |

## 3. Type

| Role | Token | Family | Use |
| --- | --- | --- | --- |

## 7. Layout

- The shell has two regions: the workspace, filling the window at the shell inset, and the status line below it. There is no global header and no navigation rail; each view's first row is its title strip, and the status line leads back to the fleet and lists the scope's windows. Every view fills the workspace exactly, its content kept out of the workspace's height by size containment, so its title strip stays and whatever is longer scrolls vertically in the view's own region, never sideways; the workspace itself scrolls only a view taller than the window allows, and a region with nothing to scroll hands the wheel and touch on to the one around it. The panel's glyph field fills the canvas behind the workspace in calm mode at 30% of its sign-in opacity, mixing in the fleet's names, hosts, addresses, versions and rates; it shows faintly through cards.
- Panel-scope windows are `1 nodes`, `2 subscriptions`, `3 logs` and `4 settings`; node windows are `1 overview`, `2 cores`, `3 configuration`, `4 logs` and `5 settings`. Their names are the command line's words and read the same in every language; their tooltips and accessible names are translated. Switching to another node keeps the window. `/` and `/overview` open the nodes home, and so does signing in. The command line opens with Ctrl or Cmd+K anywhere, `:` outside fields, editors, menus and dialogs, or the command action, but not under a modal layer. It takes `help`, `clear` and `exit`, which signs out, a window's number, `open <window>`, `goto <node> [window]`, `filter [text | state:<state> | tag:<tag>]` and `start`, `stop`, `restart` and `update` with a target: a node's name, a glob such as `hk-*`, `tag:<tag>` or `all`, resolved in the browser, and `reboot`, which restarts the panel after `[y/N]` with a pending line and then its outcome, sharing one restart at a time with the status line's action. Commands that only open a window, a node or the filtered home close the box and leave no result; `help` prints the verbs in the completion list's columns and the window numbers, without a footnote; anything else unknown prints `command not found` in danger. Tab completes verbs, windows, node names, tags and targets. A batch that interrupts, and any batch on more than one node, first prints its count, up to five names and what it interrupts, and asks `[y/N]`; only y proceeds. Each node's result prints as it finishes, one line a node, then the summary; nodes that cannot answer fail on their own line, and `update` runs one node at a time and stops at the first failure. Closing the box never cancels a batch.
- The nodes home has the title strip (state tabs all, online and offline with counts, a tag filter when any node has tags, search, a selection toggle, adding a node; below 48rem the tabs keep the first line), the key figures (running cores, their line naming only the stopped, not enabled and unknown ones there are, live traffic with both directions summed, active connections with the online nodes, this period's usage summed but never a summed quota; on a phone they scroll with the panes) and the panes in a grid on one card, 16px in and 12px apart, that scrolls inside it; the card stays while the fleet loads, fails to load, has no nodes or matches nothing, and holds that state in the panes' place. Offline nodes lead, then nodes over quota, and the rest follow by name; live load never reorders them. With no nodes the screen leads with the primary action that adds one. A click opens a node; selection mode, entered from the strip's toggle, Ctrl or Cmd click, Shift click, a touch held for 500ms or Space on a focused pane, makes a click toggle the pane and Shift extend from the last one toggled, while Enter, a middle click and the context menu still open the node; Escape, clearing the selection or the toggle leaves it and clears it. The selection's batch actions (start, stop, restart, install a core at an exact catalog version, update) each confirm in a dialog that names the nodes and what the action interrupts, then report in the command output.

Enrolling asks for the code at `code>`, after re-enrolling warns that it replaces the enrollment; unenrolling prints the panel it leaves in danger and asks `[y/N]`. Clicking the window's free space focuses the input unless text is selected. The sign-in field stays behind the terminal, calm: 60% of its sign-in opacity, still under the pointer, mixing the node's own values into its text, rippling once from the window on each status refresh, and moving or fading the glyphs the window covers.

## 8. Rules

Do and don't:
- Derive every accent-tinted value from the saved accent. A hard-coded tint breaks as soon as another colour is saved.
- Keep blur out, and translucency to content surfaces at 90%. Blur repaints under every live row, and glyphs behind typed text, menus, scrolled rows or dense live figures read as content or flicker.
- Keep gradients out of working views and colour a state only with a state colour. The cell meter's scale and the hatched unknown state are data encodings, not decoration, and a state in the accent disappears under a palette of the same hue.
- Use compact actions only in toolbars, table rows and pagination, and embedded actions only inside a field, card or tool cluster; keep a bar's controls flat and a form's fields bordered, with no filled primary action in a title strip. Mixed heights break row alignment, a bordered or filled control in a bar competes with the content below it, and a flat field in a form loses its edge.
- Style new work with component variants and utilities on the instance, read values only from tokens, and use only the type steps and weights above. Page-level styles and literal values are how the views drifted apart, and off-scale text breaks the hierarchy between data and labels.
- Write client, format and protocol names in lower case in the interface, protocols by their sing-box type: sing-box, mihomo, loon, vless, hysteria2, even at the start of a sentence; name share links by the protocols they hold, never as share links; keep the clients' own keywords untranslated as their configuration writes them: DIRECT, REJECT, DOMAIN-SUFFIX, RULE-SET, ipcidr, and group types in the channel's client's spelling (select and url-test, selector and urltest in sing-box); and keep window names as the command words in every language, translating only their tooltips and accessible names. Mixed casing made one list of formats read as different kinds of thing, "share links" read as one more protocol, a translated keyword hides the word the configuration uses, and a translated tab that reads differently from what `open` and `goto` take breaks the line between clicking and typing.
- Give every message and result a place that is always there, such as the form's message slot, the command output or a toast, keep a pane's rows on one line, and end a one-line message in a slot without closing punctuation, from the panel or the server. A line that appears in the flow or wraps moves what the user was about to touch.
- Give a node card that opens or toggles the pointer cursor over all its content, grabbing only while it is dragged, and keep every node card's text unselectable. A card is one action, so a text cursor over its readings, or a selection that a press and a small drag leave behind, reads as if the text were the target.
- Render a list as one block divided by hairlines, never as items that each draw a full border; only node cards (the fleet's panes, the pool's nodes and a group's candidates, a chosen one marked as a selected pane) stand apart as cards in 12px gaps. Separate borders double every edge and turn a dense list into noise, while a node card is an object with its own title bar.
- Keep the node's name and state visible in every node-scope view, and confirm every batch and destructive action with the nodes it acts on and what it interrupts. An action on the wrong node is the most expensive mistake in a fleet, and a fleet-wide one sent by mistake interrupts every proxy at once.

Overrides of the global guide:

## 9. Tokens in code

- `web/packages/shared/src/styles/tokens.css` holds every token and nothing else: the root scope, the dark scope `:root.dark, :root[data-resolved-theme='dark']`, the more-contrast and coarse-pointer overrides, and the `@theme inline` block that exposes tokens to Tailwind. `base.css` holds element defaults and `components.css` shared component classes; `global.css` imports Tailwind and the three files in that order.
- Component roles use the shadcn names (`--background`, `--foreground`, `--card`, `--popover`, `--primary`, `--muted`, `--accent`, `--border`, `--ring`, `--chart-*`), read through utilities such as `bg-card`, `text-muted-foreground` and `border-border`. Product tokens use the `--color-*`, `--space-*`, `--radius-*`, `--control-height*`, `--shell-*`, `--pane-*`, `--shadow-*`, `--dur-*`, `--ease-*` and `--z-*` prefixes and are read with `var()`. A product token never reuses a component role name with another meaning, and no token is an alias of another: code reads the names in sections 2 to 5. Utilities follow the scales: `rounded-md` is R/2, `rounded-lg` and `rounded-xl` are R, `rounded-[var(--radius-window)]` is the floating step; sizes are `text-2xs`, `text-xs`, `text-compact`, `text-sm`, `text-base`, `text-xl` and `text-2xl`; weights are `font-normal`, `font-medium` and `font-semibold`.
- `web/apps/panel/src/theme/appearance.ts` derives the tokens in section 2's derivation table and the radius tokens from the saved `{ theme, color, radius }`; the defaults are `system`, `#6D4ED1` and 12, and the presets `#6D4ED1`, `#2563EB`, `#0891B2`, `#15803D`, `#C65B13` and `#BE185D`. `ThemeProvider` writes them on the document root, from the appearance meta the server fills; before scripts load, the server paints the saved theme's `--color-canvas`.
- Shared patterns live in `web/packages/shared/src/components`, the data table among them (`ui/table`, its density and cell kinds): the glyph field, the prompt input, the cell meter and the terminal parts both apps use (input line, prompt label, buffer and its entries, readout rows and window marks); their classes, such as a terminal line's typing keyframes, sit in `components.css`. The component library is shadcn `base-nova` on Base UI with lucide icons (`web/packages/shared/components.json`), rule set icons coming from `@tabler/icons-react` in the panel's `rule-set-icons.ts`; patterns map to `components/ui` primitives and the shared components beside them. Tokens the shadcn CLI adds go into `tokens.css`.
- To add a token: give it light and dark values in `tokens.css`, derive it in `appearance.ts` when it depends on the accent, register it in `@theme inline` when components need a utility, and add its row here, in one change. Code that paints, such as charts, reads tokens with `getComputedStyle(document.documentElement)` and redraws when the theme or appearance changes.

## 10. Showcase

The two sign-ins are the only showcase surfaces and share one terminal prompt. They have no card or visible heading: below a first row with the wordmark, theme and language, the prompt sits at the window's centre in the data face. The node console asks for its password after a `$` in the accent; the panel asks `login:` for the email and `password:` below it, its labels in the accent, Enter on the email moving to the password. Each line draws its characters, or for a password a dot in a wider cell popping in, with a blinking block cursor at the end, a bar between characters and the selection as an accent band over whole cells; the password line ends in the visibility toggle and an embedded submit. A placeholder, in weight 300 at reduced contrast, shows only while its line is empty and unfocused. A refused attempt shakes the prompt once and keeps a danger border on it, and the line the refusal is about, until typing resumes; its message goes to a danger toast, which a further refusal replaces and typing again closes. A sign-in turns the prompt success-green and holds 520ms; the node's prompt then morphs into its terminal window, the panel's cross-fades into the shell. While checking the session each shows a spinner, and an unreachable service shows a card at 24rem with a retry.

Behind both a canvas of protocol names, settings, documentation addresses and log fragments in the data face fills the window below the first row in three layers at 10, 12 and 14px and rising opacity, longer fragments further back; each layer is scattered by best-candidate sampling, tilted mostly within 12°, whole at the window's edges and kept a narrow margin from the prompt, so layers overlap without leaving holes. The pointer pushes and leans glyphs aside, nearer layers further, a keystroke streams a few toward the prompt, a refusal sends a danger shock outward and a sign-in a success wave across; while idle one glyph at a time types a new text with a cursor at its end. The field pauses while the page is hidden and is a still field that only changes colour under reduced motion.
